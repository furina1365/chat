# 代码交接与因素矩阵

1. **沿真实入口查基线**。从实际请求、事件或命令入口读源码，核对相关测试与必要的 Git 历史，记下调查基线。排查缺陷用 [systematic-debugging](../implement-and-document/references/skills/systematic-debugging/SKILL.md) 确认根因。
2. **画 ASCII 调用链**。用 `text` 代码块标出跨层调用、异步回调和与改动有关的结果，关键节点写符号与 `仓库相对路径:行号`，块后用可点击链接跳到核对过的 `#L行号`。历史行为注明提交与查看方式，源码结论随段链接。
3. **强制挖出影响因素并列测试矩阵**。这一步每次必做，不能因为改动看着简单就省掉。围绕本次改动触及的代码路径，列出所有会影响结果的因素——**重点排查代码里藏着、需求里没写的隐藏因素**，例如并发与竞态、定时器重排与超时叠加、Reactor/Proactor 双后端行为差异、背压/部分读写/半关闭、排队等待与非流式分支、幂等/重放/租约、编译宏或配置边界。按“因素（标明是否隐藏）| 场景与输入 | 测试接缝/观察点 | 预期行为 | 红→绿状态”整理成因素测试矩阵，写明每项用自动化测试还是真实入口集成验证。
4. **写清改动落点与验收步骤**。说明改动落在哪层、为什么落在这里，记下不在此改动范围内但会影响判断的边界。给出从实际入口复现和验收的前置条件、命令、输入和预期，供后续按 TDD 逐项执行。[测试手册](../../../docs/testing.md)

按 [AI 执行模板](../execute-change/references/execution-template.md) 写入与审核文档同目录的 `<主题短名>-execution.md`，默认目录为 `docs/changes/`。已有实测记录时保留原始结果。[SSE 执行文档](../../../docs/changes/sse-idle-regression-execution.md)
