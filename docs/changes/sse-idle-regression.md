# 【测试】网页 AI 对话 - chat - SSE 空闲超时回归

网页用户发送消息后，`/api/chat` 会在同一条连接上不断返回正文。模型暂时没给内容时，聊天服务会定期发心跳。连接上如果一直没有成功收发，服务会在空闲阈值到达后回收连接。[聊天接口](../api.md) · [心跳](../../backend/http/src/Http.cc#L81)

之前这组行为靠本机手动检查。现在一个脚本就能启动 Reactor 和 Proactor，用本机模拟模型和临时 MySQL、Redis 跑同一组用例。每套后端各跑七项，其中一项让客户端停止读取，另一项让客户端每秒只读 1 字节。脚本确认这两种情况下服务端都一直写不出去，再计时检查连接何时回收。[Issue #5](https://github.com/furina1365/chat/issues/5) · [运行方法](../testing.md#91-sse-空闲超时回归)

两套后端共 14 项通过。持续发正文和只有心跳的连接都撑过 60 秒，约在第 64 秒收到 `done`。静默和半截请求从最后一次活动起约 60 秒关闭，停读和极慢读取的连接也在持续写不出去约 60 秒后回收。模型约在第 3 秒超时时，网页收到 `error`，历史保留已收到的正文并把回复记为失败。

回归跑的是 Linux 本机连接、实际聊天服务和模拟模型。用户主动停止或断开后的模型取消由 [#3](https://github.com/furina1365/chat/issues/3) 跟踪。

## MR #6 审查修订

原来的脚本收到 `done` 后可能把少了最后一个空行的响应算成完整回复。传入复制的二进制也可能让两个 Reactor 的结果被当成双后端通过。现在脚本检查 HTTP 分块的结束标记，并在启动前核对每个 `server` 编译时选中的网络后端。

测试服务给本机模拟模型的地址加代理豁免。项目技能示例用 `python3` 启动脚本，从 Git 导出的副本上已验证。开启代理时，双后端 14 项回归通过，代理记录到 0 次模型请求。[审查复验](sse-idle-regression-execution.md#mr-6-审查修订)
